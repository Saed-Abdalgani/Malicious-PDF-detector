\begin{abstract}
This report documents the implemented Phase 0--7 workflow for a defensible
malicious-PDF detection experiment. The remediation enforces a minimum two
million-row training partition, at least 99.5\% benign prevalence, feature-only
safe data, group-temporal evaluation, versioned intelligent features, and exact
batch/inference parity, fair tree/neural comparison, validation-only calibration
and thresholds, one-shot sealed-test analysis, gated deep explainability, and a
safe inert-PDF adversarial defense benchmark. No approved 2.65-million-row
primary feature table is currently configured; consequently, no final model
metric or performance claim is reported. This distinction between verified
controls and pending empirical evidence is intentional.
The pipeline is designed and validated for multi-million-row streaming
workloads. This statement describes the implemented bounded-batch and
disk-backed architecture; it does not claim that a production run has already
processed two million real training rows.
\end{abstract}

\section{Safety and data policy}

Training accepts only approved, checksum-pinned CSV, JSONL, or Parquet feature
tables. A source must provide a license, version, exact SHA-256, explicit schema
mapping, opaque sample and group identifiers, source, timestamp, label, and label
confidence. Raw PDF bytes, extracted JavaScript, payloads, embedded files,
executables, archives, and sample URLs are rejected. Invalid evidence is
quarantined using reason codes and hashed identifiers, never copied raw.

The 10,025-row CIC-Evasive-PDFMal2022 table is registered only as a disabled
supplementary benchmark. It cannot satisfy scale or production prevalence and is
not silently promoted. The missing primary source is an external dependency, not
a reason to fabricate observations or relax the gates.

\section{Phase 0: experiment truth}

An experiment identity binds dataset version, feature-schema version, split
version, code commit, random seed, complete configuration hash, and creation
time. Every trusted artifact receives a checksum sidecar. Deployable-model
metadata must also bind the verified dataset-quality report, sealed split,
feature pipeline, and validation-selected threshold. Atomic writes and
independent verification reject partial, stale, missing, or tampered artifacts.

Pre-remediation results are preserved only in a checksummed archive. The active
summary currently states that the data gate has not passed and its final metric
field is null.

\section{Phase 1: safe scalable validation}

Input is processed in bounded batches. Exact column names, numeric types,
integer count semantics, finite values, domains, missingness, opaque IDs, binary
labels, confidence, source/group identity, and UTC time are checked before
writing typed Parquet. Count, boolean, and continuous feature storage uses
32-bit integer, 8-bit integer, and 32-bit floating-point representations after
overflow and integrality validation.

A disk-backed two-pass identity index removes all repetitions of duplicate IDs
and every row associated with a contradictory label. Equal feature vectors are
reported as a possible collection warning but never treated as proof that two
documents are identical. A source/time-only diagnostic measures label shortcut
risk.

The transformation manifest binds the input checksum, quality report, and every
clean and quarantine part with its checksum and row count. An independent
verifier repeats the scale, prevalence, file-list, checksum, and count checks
before Phase 2.

\section{Phase 2: leakage-resistant split}

Complete groups are sorted by earliest observation time and assigned to train,
validation, and sealed test windows. The split must satisfy:

\begin{itemize}
  \item at least 2,000,000 train and 250,000 validation/test rows;
  \item at least 99.5\% benign prevalence in each partition;
  \item zero sample and group overlap; and
  \item strict train-before-validation-before-test temporal order.
\end{itemize}

Feature rows and identity manifests are stored separately. Every part, row and
group count, prevalence, time range, and logical manifest is checksummed. A seal
prevents overwriting the version. A streaming verifier independently reconstructs
the evidence before a consumer proceeds. Median imputation, constant detection,
neural clipping, and standardization are learned from train only; test is not
opened during model training or threshold selection.

\section{Phase 3: intelligent feature contract}

The base contract defines 37 fields by name rather than position. Each definition
contains type, unit, range, missing policy, extraction formula, rationale,
aliases, and train/live availability. Deterministic engineering adds:

\begin{itemize}
  \item log-stable views of heavy-tailed counts and sizes;
  \item per-object, per-page, per-stream, and per-KiB densities;
  \item absolute and normalized structural consistency gaps;
  \item domain-motivated active-content interactions;
  \item entropy, concentration, and object/metadata complexity; and
  \item parser-health, disagreement, missingness, and clipping indicators.
\end{itemize}

Every final model input has a formula, unit, range basis, rationale, and lineage.
For neural preprocessing, the catalog contains the exact train-learned clipped
and standardized bounds. File size is tested as a one-feature shortcut using
train-selected direction and held-out validation ROC separability. Raw creator
and producer strings are excluded as high-cardinality provenance shortcuts.

\section{Bounded PDF analysis and parity}

The live extractor performs static analysis only. It canonicalizes PDF name
escapes and syntax outside opaque stream bodies, combines lexical, parser, and
bounded logical-graph views, and never renders pages or executes JavaScript.
Limits cover file size, time, pages, resources, graph depth/nodes, streams,
filters, decompressed bytes, expansion ratio, and object streams. Typed status
distinguishes parser failure, recovery, malformed structure, timeout, and
resource limits; critical conditions recommend abstention rather than being
silently labeled malicious.

Exact parity is tested in two ways: 100 sanitized schema-v2 rows through record
and batch APIs, and 100 locally generated inert, valid PDF fixtures through live
extraction and batch transformation.

\section{Phase 4: fair model comparison}

The required set comprises an always-benign baseline, regularized logistic
regression, Extra Trees, LightGBM, histogram XGBoost, the fully connected MLP as
a control, and an FT-Transformer. Every non-dummy family has unweighted and
cost-sensitive variants. The FT-Transformer uses per-feature numerical tokens,
feature-identity embeddings, multi-head self-attention, pre-normalized residual
blocks, GEGLU feed-forward layers, dropout, and weighted asymmetric focal loss.

Configuration selection uses complete groups from a deterministic
source/label/time-stratified subset of train and expanding temporal train folds.
Finalists are refitted on the full 2M-or-more train partition for three fixed
seeds. Disjoint group-temporal validation roles fit calibration, select among
identity/Platt/isotonic calibration, and lock five operating thresholds. The
primary rule is validation F2 subject to FPR at most 0.1\%. A neural model is
selected over the best tree only if its paired group-bootstrap interval excludes
zero and its calibration and inference-cost rules pass. Test content remains
sealed throughout Phase 4.

\section{Phase 5: metrics and error analysis}

Malicious PDF is the positive class. Precision $=TP/(TP+FP)$ measures alert
quality; Recall $=TP/(TP+FN)$ measures detection coverage. F1 gives equal weight
to both, while
\[
F_{\beta}=\frac{(1+\beta^2)PR}{\beta^2P+R}
\]
provides the precision-weighted $F_{0.5}$ and recall-weighted $F_2$ views. Full
ROC-AUC describes ranking across thresholds, whereas partial ROC-AUC at FPR
0.1\% and 0.01\% focuses on the plausible operating region. Average precision
summarizes the precision--recall curve, whose no-skill baseline equals malicious
prevalence rather than 50\%.

The locked report also includes specificity, FPR/FNR, MCC, balanced accuracy,
Brier score, expected calibration error, TP/FP/TN/FN, and false positives per
million benign PDFs. It evaluates threshold 0.5, validation maxima for F1/F2,
and validation FPR limits of 0.1\%/0.01\%. Complete-group stratified bootstrap
intervals, paired differences, deployment subgroups, reliability, PSI and
Jensen--Shannon drift, and hashed numeric-only hard-error profiles are required.

An exclusive ledger permits one test claim per experiment. It binds the
experiment, sealed split, and champion hashes. A failed claim cannot be retried
under the same version. Final metrics enter the active summary only after all
tables and figures have been checksummed and the ledger closes.

\section{Phase 6: deep explainability}

Phase 6 never reopens sealed test. It consumes only a bounded feature-only
handoff with hashed identifiers produced during the authorized Phase 5 run.
Train supplies the real stratified SHAP background, prototypes, data audits, and
all retraining; validation supplies permutation, ALE, interaction, sanity, and
faithfulness evidence.

Global evidence combines held-out average-precision permutation loss,
model-native importance, TreeSHAP or neural gradient explanations, ALE,
domain-driven interactions, and feature-family retraining ablations. Stability
uses model seeds, validation-time slices, and 100 attribution bootstraps. Label randomization, a fitted random-noise
feature, deletion/insertion against random order, source/time shortcuts, and
method disagreement act as negative and faithfulness controls.

Representative TP, TN, FP, FN, high/low-confidence, and parser-abstained cases
include probability, locked threshold, supporting and opposing drivers, raw
values when available, transformed values, train percentiles and subgroup
context. Counterfactuals use complete observed benign train rows and are marked
diagnostic rather than causal. SHAP alone cannot produce a conclusion; failed
sanity or faithfulness checks produce an explicit no-conclusion report.

\section{Phase 7: safe adversarial evaluation}

The Phase 7 harness generates inert PDFs locally and never downloads malware,
renders a document, or persists fixture PDFs in reports. Network links, embedded
files, launch actions, executables, and harmful scripts are prohibited. Every
mutation is envelope-checked and parsed by a strict non-rendering validator;
when qpdf is installed, \texttt{qpdf --check} is also required and recorded.

The suite exceeds eight valid families: PDF name escaping, whitespace/comments,
object renumbering, incremental revisions, bounded compressed object streams,
logical action relocation, benign stuffing, xref representation changes, inert
string encoding, page/metadata/image inflation, bounded nesting, duplicate-key
parser-policy disagreement, combined mutations, and query-selected worst cases.

Pre/post evidence compares literal tokens, canonicalized multi-view signals, the
calibrated champion, and champion-plus-abstention. Reports include attack success,
robust marker Recall/F2, probability drop, mutated-benign false-positive rate,
clean deltas, parser failure/abstention, latency, and peak memory. The positive
fixtures contain inert security markers and are not malware ground truth.
Adversarial training, monotonic constraints, and sandbox escalation remain
explicitly future unless approved labeled data or external infrastructure exists.

\section{Current limitations and next action}

The implemented controls do not prove that the production empirical gates have
passed. The repository lacks an enabled, approved, checksum-pinned primary table
with at least 2.65 million genuine observations. Therefore no production clean
layer, sealed split, fitted Phase 3 pipeline, trained champion, metric table,
production explainability conclusion, or robustness claim exists yet.

The next valid action is to obtain written approval for an institutionally
provided feature-only table, register its exact provenance and checksum, and run
the Phase 1--4 command without changing the configured thresholds. After Phase 4
evidence is reviewed, Phase 5 may open the sealed test exactly once. If such data
cannot be obtained, the project scope must be renegotiated with the professor;
synthetic or unsafe replacement data is not acceptable.

\section{Conclusion}

Phase 0--7 now supplies a fail-closed, auditable workflow suitable for the
professor's requested experiment. The implementation is deliberately honest
about the remaining data dependency. Credible future metrics must come from the
sealed natural-prevalence evaluation, not from legacy results or an easier
surrogate dataset. Phase 6--7 production execution remains gated on the approved
data and checksummed upstream artifacts.
